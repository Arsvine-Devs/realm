[返回文档组](./README.md)

> 文档状态：历史整改记录，不是当前执行清单。独立 `arsvine-content` 仓库已废弃；当前接口边界以 Realm/Platform 源码和当前执行规格为准。本文中的旧 GitHub fallback、Admin 兼容面和环境快照只保留用于追溯。

本文把当前审计发现转换为可逐项确认的整改候选。它不是执行授权，也不代表下面的配置已经变更；已经执行的项目和验证结果记录在“本轮执行记录”。除已明确记录的项目外，本轮不修改应用代码、Content、Admin、DNS、COS、EdgeOne、Vercel 环境变量或证书。

## 状态与执行规则

- `NEEDS_CONFIRMATION`：已有明确整改方向，但会改变线上行为、权限、域名、证书或数据保留，需要确认后执行。
- `BLOCKED_BY_AUTH`：需要用户提供或确认密钥、Owner/WebAuthn、云账号权限或外部系统认证；先记录，继续其它项目。
- `NEEDS_DECISION`：配置可能是冗余或策略选择，先验证用途和成本，不把偏好当成缺陷。
- `DEFERRED_TEMPORARY`：临时活动或历史项目，等生命周期节点再处理。
- `NOT_A_DEFECT`：已核验但当前没有足够证据认为需要改动。
- `APPLIED`：已按确认执行并完成目标状态核验。
- `VERIFIED_NO_CHANGE`：已核验现有配置满足目标，没有执行重复或无必要修改。
- `DECIDED_NO_CHANGE`：用户已明确选择保留现状，不执行该候选修改。

执行任何获得批准的项目时，都要先保存原配置/证书/记录，做窄范围验证，再保留可回滚窗口。腾讯云控制面证据和当前快照见 [`TENCENT_CLOUD_SNAPSHOT.md`](./TENCENT_CLOUD_SNAPSHOT.md)。

## 当前不建议直接改动的项目

- COS 私有 ACL + EdgeOne 回源策略已经形成可用的访问边界；在没有替代链路和回归验证前，不把公共媒体桶改成匿名公共读。
- COS 版本控制、生命周期、EdgeOne HSTS/缓存 TTL 等项目需要结合成本、恢复目标和真实消费者决策，不以“开关越多越安全”作为判断依据；公共 COS 全球加速已按本轮确认关闭。
- Vercel Geo、ISR、Cron、Neon HTTP driver、Upstash fail-open 和 provider-neutral 接口是既有架构边界；若没有已批准的 VPS 迁移实现，不提前新增通用抽象或替换运行时。

## 建议确认方式

可以按 ID 批准，例如：`CLOUD-01`、`CLOUD-03`、`CONTENT-02`。获得确认后只执行已批准项目，涉及密钥、Owner/WebAuthn、主账号/CAM 或通知接收人的项目会在准备完成后再次指出具体认证/输入缺口；其它不受阻项目继续推进。
